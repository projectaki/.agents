# Investigation

You own the answer. Plan, route, and write.

An investigation is read-only. It produces an explanation with citations, or a recommendation. It does not change code.

1. Trace the code that the question is about. For a broad question, delegate the exploration to a read-only background subagent, according to the delegation reference. For a question about why the code is this way, also use the **why** skill.
2. Write the answer with these sections: Overview, Key concepts, How it works, Where things live, Gotchas. If the question is a choice between options, write a recommendation with a tradeoffs table instead.

No pull request and no **architect**. If the answer leads to a code change, say so, and continue with the Bug fix or Feature playbook.

**Reply:** the answer. For an "are we sure?" question, give your real judgment and the reasons.
