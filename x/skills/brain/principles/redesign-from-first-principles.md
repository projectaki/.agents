# Redesign from First Principles

When you add a new requirement to an existing design, do not attach it to the side of the design. Redesign as if the requirement had been a basic assumption from the start.

- Read all affected files and understand the current design.
- Ask: "If we wrote this from scratch with this new requirement, what would we build?"
- Apply the change everywhere it is referenced: types, documents, examples, and design notes.
- Plan the whole redesign, then deliver it in small steps.

When a requirement fits the existing extension points, extend the code. When it does not fit, redesign.
