# Attack the Premise

When two or more fixes that depend on the same belief fail the same check, doubt the belief, not the fixes. Each failed fix is evidence that the belief is wrong. A third fix on the same belief puts effort where the evidence already says the cause is not.

- **Write the belief down.** Write it as the one sentence that every failed fix assumed.
- **Test the belief before the next fix.** Find an observation that comes out differently if the belief is false, and make it. Look at the pattern of the failures, not only at their size. Make the check something that you can run again, according to [Build the lever](build-the-lever.md).
- **Follow the evidence.** If the evidence contradicts the belief, the cause is somewhere else. Look for what the failures have in common that the belief did not predict. If the evidence confirms the belief, ask the next "why", according to [Fix root causes](fix-root-causes.md). The earlier fixes may have treated a result and not the cause.
- **Remove the condition. Do not compensate for it.** If one part always ends up on the losing side, change what puts it there. A mechanism that cleans up afterward leaves the cause in place and adds work on every run.

Do not start the next fix before you write the belief down and test it.

This principle is different from [Redesign from first principles](redesign-from-first-principles.md). That principle rebuilds a design around a new requirement. This principle questions a fact that the current design assumes.
