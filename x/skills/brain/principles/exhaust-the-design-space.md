# Exhaust the Design Space

For a new UI interaction or an architecture decision that has no example in the codebase, build 2 or 3 competing versions in code. Compare them side by side, and let the result decide the design. This also applies to product design choices where the user experience depends on how something feels, not on logic.

Many problems appear only when code exists. A design written in advance as text changes often, and the time spent on it is lost. Code versions show these problems early.

- Make the versions clearly different in shape, not small changes of one design.
- Keep the versions cheap. They exist to decide the design, not to ship.
- Compare the versions on the same task, and state why the chosen version is better.
