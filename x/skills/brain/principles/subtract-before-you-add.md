# Subtract Before You Add

When you change a system, remove complexity first, then build. Make removal the default. After each change, leave the design a little simpler, and as capable or more capable, with the same or a smaller public interface.

- Remove dead code and unused paths before you build on top of them.
- Cut before you polish. Get to the minimum first, then improve quality.
- Design for how the code is actually used, not for edge cases that might happen.
- Do not add validators, parsers, or guards beyond what the requirement needs.
- Simplify prompts. Remove repeated instructions and large templates.
- In finished work, delete a reference that adds nothing new. Do not leave an empty placeholder.
